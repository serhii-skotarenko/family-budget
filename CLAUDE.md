# family-budget — CLAUDE.md

## Що це

Сімейний бюджет: Telegram-бот для трекінгу витрат (MVP) + місце під майбутній веб-дашборд.

## Структура репозиторію

- `tg-bot/` — Telegram-бот (MVP), Python
- `dashboard/` — зарезервовано під майбутню веб-аппку (стек ще не обрано)
- `docs/` — продуктова документація, вимоги, рішення

## З чого починати

Перед будь-якою імплементацією прочитай `docs/requirements.md` — там 7 епіків і 9 user stories з acceptance criteria для MVP, чернетка моделі даних (Household/Member/Category/Expense) і бэклог Phase 2. Це єдине джерело правди по скоупу MVP. Якщо код і документ розійдуться — редагуй код під документ, а не навпаки, без окремого запиту.

## Стек (tg-bot, MVP)

- Мова: Python 3.12+
- Фреймворк бота: aiogram 3.x
- БД: SQLite (одного файлу достатньо для 2 користувачів; вибір ORM — на розсуд імплементації, напр. SQLAlchemy або aiosqlite напряму)
- Хостинг: хмарний PaaS (Railway або Fly.io — конкретний провайдер ще не обрано). Тримай деплой портативним: Dockerfile + конфіг через змінні середовища, без прив'язки до фіч однієї конкретної платформи
- Конфіг через env: `TELEGRAM_BOT_TOKEN`, whitelist дозволених Telegram ID (напр. `ALLOWED_TELEGRAM_IDS` — comma-separated)

## dashboard/

Поки порожньо — заплановано на майбутнє (після MVP бота), стек ще не обговорювався. Не чіпати без окремого запиту.

- Python: ruff + black для лінту/форматування

## Статус

MVP бота реалізовано в `tg-bot/` (aiogram 3 + SQLAlchemy 2 async + SQLite/Alembic,
запуск через Docker) і пройшов ручну приймальну перевірку двома користувачами.
`dashboard/` — усе ще порожньо.

Деплой-провайдер: **Railway**. Специфіка платформи зведена до `tg-bot/railway.json`
і налаштувань сервісу (Root Directory `tg-bot`, том на `/data`); сам образ
лишається портативним. Покрокова інструкція — у `tg-bot/README.md`.
