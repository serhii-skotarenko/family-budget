# Telegram-бот для сімейного бюджету

## Мета

Telegram-бот для трекінгу витрат по категоріях і користувачах усередині родини (на старті — 2 користувачі: Сергій і дружина), з можливістю переглядати/редагувати записи та отримувати текстові звіти за тиждень/місяць/рік. User stories нижче призначені для передачі Claude Code на імплементацію.

## Рішення з брейншторму (2026-09-06)

- **Учасники MVP:** тільки 2 користувачі (whitelist за Telegram ID), обидва належать до однієї спільної "сім'ї"
- **Права доступу:** обидва користувачі можуть редагувати й видаляти будь-які записи, не тільки свої
- **Категорії:** гібрид — готовий базовий список + можливість додавати власні
- **Додавання витрати:** покроковий діалог бота (сума → категорія → опис опційно), без вільного тексту та без OCR чеків на цьому етапі
- **Звіти:** тільки текстові (тиждень/місяць/рік), без графіків
- **Валюта:** лише UAH, без мультивалютності
- **Проактивні сповіщення:** не потрібні на MVP (бот ніколи не пише першим)
- **Прибрано з MVP** (за результатом брейншторму): облік доходів, ліміти по категоріях, цілі накопичення, регулярні платежі — все це переїхало в Phase 2, оскільки або не є критичним для базового трекінгу витрат, або залежить від проактивних сповіщень, яких немає в MVP

## MVP — епіки та user stories

### Епік 1. Доступ і сім'я

**US1.1 — Whitelist дозволених користувачів**
Як власник бота, я хочу налаштувати список дозволених Telegram ID при розгортанні, щоб доступ мали тільки я і дружина.

Acceptance criteria:
- Бот зберігає whitelist Telegram ID (конфіг/env/БД)
- Повідомлення від ID поза whitelist ігноруються або отримують відповідь "доступ заборонено"
- Обидва дозволені ID належать до однієї спільної "сім'ї" й бачать спільні дані
- `/start` для дозволеного користувача показує привітання і коротку довідку по командах

### Епік 2. Категорії витрат

**US2.1 — Базовий список категорій за замовчуванням**
Як користувач, я хочу мати готовий набір категорій одразу після старту, щоб не налаштовувати все з нуля.

Acceptance criteria:
- При першому запуску сім'ї бот створює базовий набір категорій: Їжа, Транспорт, Комунальні, Оренда житла, Розваги, Здоров'я, Одяг, Діти, Інше
- Список категорій доступний командою `/categories`

**US2.2 — Додавання власної категорії**
Як користувач, я хочу додати свою категорію, щоб точніше класифікувати витрати, специфічні для нашої родини.

Acceptance criteria:
- Команда додає нову категорію до спільного списку сім'ї
- Дублікати (регістронезалежно) відхиляються з поясненням
- Нова категорія одразу доступна другому користувачу при виборі категорії під час додавання витрати

### Епік 3. Додавання витрати

**US3.1 — Додавання витрати через покроковий діалог**
Як користувач, я хочу додати витрату через послідовність питань бота, щоб швидко залогувати покупку, не думаючи про синтаксис команд.

Acceptance criteria:
- Користувач ініціює додавання командою/кнопкою (напр. `/add`)
- Бот питає суму → валідує, що введено додатне ціле число гривень (без копійок)
- Бот показує inline-клавіатуру зі списком категорій сім'ї для вибору
- Бот питає опис (опційно, з кнопкою "Пропустити")
- Після підтвердження бот зберігає запис: сума, категорія, опис, автор (за Telegram ID), дата/час
- Бот показує підсумкове повідомлення зі збереженим записом
- Діалог переривається командою `/cancel` на будь-якому кроці без збереження

### Епік 4. Перегляд витрат

**US4.1 — Список останніх витрат**
Як користувач, я хочу переглянути список останніх витрат, щоб перевірити, що все залоговано правильно.

Acceptance criteria:
- Команда (напр. `/list`) показує N останніх записів з датою, сумою, категорією, автором, описом
- Кожен запис має спосіб швидко перейти до редагування чи видалення

**US4.2 — Фільтрація витрат**
Як користувач, я хочу відфільтрувати витрати за періодом і/або категорією, щоб знайти конкретні записи.

Acceptance criteria:
- Підтримуються фільтри: період (сьогодні/тиждень/місяць/довільний діапазон), категорія, автор
- Результат показується списком, аналогічним `/list`
- Порожній результат — зрозуміле повідомлення ("Витрат за цей період не знайдено")

### Епік 5. Редагування витрати

**US5.1 — Редагування будь-якого запису**
Як користувач, я хочу відредагувати будь-який запис витрати (свій чи партнера), щоб виправити помилку введення.

Acceptance criteria:
- З перегляду списку/фільтра можна вибрати запис і відредагувати суму, категорію або опис
- Видно, хто востаннє редагував запис і коли (прозорість, бо редагувати можуть обидва)
- Оригінальний автор запису не змінюється при редагуванні іншим користувачем

### Епік 6. Видалення витрати

**US6.1 — Видалення запису**
Як користувач, я хочу видалити помилково доданий запис, щоб він не впливав на звіти.

Acceptance criteria:
- З перегляду запису доступна дія "Видалити"
- Бот запитує підтвердження перед остаточним видаленням
- Видалений запис одразу зникає зі звітів і списків

### Епік 7. Звіти

**US7.1 — Звіт за період**
Як користувач, я хочу отримати текстовий звіт за тиждень/місяць/рік, щоб бачити загальну картину витрат сім'ї.

Acceptance criteria:
- Команда (напр. `/report`) пропонує вибір періоду: поточний тиждень (календарний, Пн–Нд за Europe/Kyiv), поточний місяць, поточний рік
- Звіт показує: загальну суму, розбивку по категоріях (сума і % від загального, відсортовано за спаданням), розбивку по користувачах за display_name (хто скільки витратив)
- Якщо за період немає витрат — звіт явно повідомляє про це, без помилки

## Модель даних (чернетка)

- **Household** (id, name) — навіть при 2 користувачах варто моделювати як окрему сутність, щоб Phase 2 (більше учасників) не вимагав переписування схеми
- **Member** (id, household_id, telegram_id, display_name)
- **Category** (id, household_id, name, is_custom)
- **Expense** (id, household_id, member_id (автор), category_id, amount, description, created_at, updated_by, updated_at)

## Уточнення після другого раунду брейншторму (2026-09-06)

- **Тиждень у звіті:** календарний тиждень, Пн–Нд, за таймзоною Europe/Kyiv
- **Точність суми:** цілі гривні (без копійок) — і при введенні, і у звітах
- **Опис витрати:** опційний, крок можна пропустити (вже враховано в US3.1)
- **Базовий список категорій:** Їжа, Транспорт, Комунальні, Оренда житла, Розваги, Здоров'я, Одяг, Діти, Інше — вважати фінальним для MVP (додано "Оренда житла" окремою категорією 2026-09-06)
- **Автор у списках/звітах:** показується ім'я (display_name), не Telegram username

## Phase 2 (поза MVP)

- Облік доходів
- Ліміти по категоріях (з попередженням при перевищенні)
- Цілі накопичення
- Регулярні/повторювані платежі з нагадуваннями

- Графіки в звітах
