# Phase 2 · Підпроєкт D — дохід і вільний кешфлоу

- Дата: 2026-09-30
- Статус: дизайн погоджено в брейнштормі, чекає ревʼю спеку
- Джерела: `docs/phase2-limits-proposal.md` (пропозиція №3), `docs/phase2-tasks.md` (T4, T19, T20)
- Гілка: `feat/phase2-income` (від `feat/phase2-connector-limits`, бо MCP-частина стоїть на коді
  PR #9)

## Контекст і мета

Бот знає лише витрати. Щомісячний дохід сім'ї (~300 000 ₴) і розрахунок «скільки лишається»
зараз живуть поза ботом — у розмові з Claude й в Excel. Мета:

1. зберігати місячний дохід сім'ї з історією змін;
2. показувати **вільний кешфлоу = дохід − витрати** у місячному й річному `/report` і в
   MCP-конекторі.

## Зафіксовані рішення

| Питання | Рішення |
|---|---|
| Модель доходу | Історія змін (append-only), як `limits`; без розбивки по джерелах; спільний на сім'ю |
| Період доходу | Місячний |
| Дохід місяця | Остання версія з `effective_from ≤ as_of`, де `as_of = min(зараз, кінець місяця − 1 мкс)`; дохід діє на весь місяць, у якому заданий |
| Зняття доходу | Немає — лише нове значення (мінімум 1 ₴) |
| Кешфлоу | Дохід − **усі** витрати (разом із разовими) |
| Поточний місяць | Факт на сьогодні, без прогнозу |
| Де показувати | Місячний і річний `/report`, MCP-конектор. Тижневий звіт — без змін |

## Модель даних

Міграція Alembic `0003_incomes` — лише таблиця `incomes`, категорії не змінюються.

### Нова таблиця `incomes`

| Поле | Тип | Примітка |
|---|---|---|
| `id` | int PK | |
| `household_id` | FK → households, `ondelete=CASCADE` | |
| `amount` | int | місячний дохід, цілі гривні, > 0 |
| `effective_from` | DateTime (UTC-naive) | момент встановлення |
| `created_by_id` | FK → members | |
| `created_at` | DateTime (UTC-naive) | |

Індекс `ix_incomes_lookup (household_id, effective_from)`. Рядки лише додаються.

## Бізнес-логіка — `services/income.py` (новий)

- `set_income(session, *, household_id, member_id, amount, now=None) -> Income` — новий рядок з
  `effective_from = now or utcnow()`.
- `income_at(session, household_id, as_of) -> int | None` — `amount` останньої версії з
  `effective_from ≤ as_of` (при рівності — більший `id`), або `None`.
- `month_income(session, household_id, month_first: date, now) -> int | None` — дохід місяця:
  `as_of = min(now, кінець місяця − 1 мкс)`; для місяця в майбутньому — `None`.
- `@dataclass(frozen=True) Cashflow(income: int, spent: int, free: int, first_month: date,
  months: int)` — `free = income − spent`; `first_month` — перший місяць, за який враховано
  дохід; `months` — кількість таких місяців.
- `cashflow(session, household_id, first: date, last: date, now) -> Cashflow | None` — для
  календарних місяців від `first` до `last` (обидва — перші числа місяців), які не пізніше за
  поточний: береться кожен місяць, для якого `month_income` не `None`; `income` — сума їхніх
  доходів, `spent` — сума **всіх** витрат цих самих місяців (межі — `period_range`-логіка
  календарного місяця за Києвом). Немає жодного місяця з доходом → `None`.

## Інтерфейс бота

### `/setincome` (новий роутер `income.py`, FSM `SetIncome` з одним станом `amount`)

1. «💰 Введіть місячний дохід сім'ї в гривнях (зараз: 300 000 ₴):» — «(зараз: …)» лише якщо дохід
   уже є. Клавіатура — «❌ Скасувати».
2. Перевірка — `parse_amount`; помилка — повідомлення, крок повторюється.
3. «✅ Дохід: <b>312 000 ₴</b>/міс (було 300 000 ₴), діє з жовтня 2026».

`/cancel` перериває діалог. Команда — у довідці `/start` і в меню команд.

### Місячний `/report`

Якщо `cashflow` за цей місяць не `None`, під рядком «Разом» (і під рядком загального ліміту,
якщо він є) додаються:

```
Дохід: 300 000 ₴
Вільний кешфлоу: 241 600 ₴
```

Від'ємний кешфлоу — `Вільний кешфлоу: −12 400 ₴ 🔴` (знак мінус U+2212 перед сумою).

Якщо витрат за місяць немає, звіт і далі каже «Витрат за цей період не знайдено.» — без рядків
доходу (як з лімітами).

### Річний `/report`

Те саме для місяців поточного року від січня до поточного. Якщо `first_month` пізніше за січень —
третій рядок: `(дохід враховано з жовтня)`. Кешфлоу рахується лише за місяці з доходом, тож
витрати січня–вересня без доходу в нього не входять.

### Тижневий звіт

Без змін.

## MCP-конектор

Доповнює спек конектора розділом «Phase 2 D».

- Новий інструмент `get_cashflow` («Дохід і кешфлоу»): вхід `start_date`, `end_date` (як в
  інших інструментах); вихід `months: [{month_start, month_end, income, spent,
  one_time_amount, free_cashflow, complete}]` для кожного календарного місяця, який перетинає
  діапазон. Місяць рахується повністю (межі діапазону його не обрізають). `income` і
  `free_cashflow` — `null`, якщо доходу в тому місяці ще не було. Місяць у майбутньому не
  повертається; `end_date` пізніше за сьогодні обрізається до поточного місяця. Понад 60 місяців
  — помилка з підказкою.
- `get_budget_overview` отримує поле `current_monthly_income: int | null`.

## Тестування

- `services/income`: версія на кінець минулого місяця (зміна після кінця не враховується);
  зміна посеред поточного місяця діє на весь місяць; місяць до першого доходу — `None`;
  `cashflow` за рік рахує лише місяці з доходом і витрати тих самих місяців; разові входять у
  `spent`.
- Міграція `0003`: створює `incomes`, категорії на базі з даними не змінює; downgrade прибирає
  `incomes`.
- Обробники: повний діалог `/setincome` (з «було» і без), невалідна сума; місячний звіт з доходом,
  від'ємний кешфлоу, звіт без доходу не змінюється; річний звіт із приміткою «з жовтня».
- MCP: `get_cashflow` — повні місяці, `null` до першого доходу, обрізання майбутнього, `complete`;
  `current_monthly_income` в огляді; інструмент має `title` і `readOnlyHint`.
